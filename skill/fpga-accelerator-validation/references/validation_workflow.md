# 验证流程与证据契约

## 输入清单

开始时寻找工程入口、源码、接口定义、工具版本、输入样本、参考答案、硬件报告与板端日志。缺少某一类时记录缺口，不生成不存在的证据。运算契约至少说明：

| 范畴 | 必须厘清的内容 | 常见误判 |
|---|---|---|
| 数据布局 | NCHW/NHWC、通道补齐、stride、padding、字节序 | shape 一样便认为数据排列相同 |
| 数值 | 有/无符号、乘法/累加宽度、溢出、舍入与饱和 | CPU 默认提升类型与 RTL 自动截断不同 |
| 控制 | 启停、复位极性、busy/done、请求序号 | 读取到前一次任务的完成状态 |
| 传输 | 地址单位、beat 宽度、缓冲区长度、TLAST、对齐 | 把元素数当作 DMA 字节数 |
| 内存 | cache line、clean/invalidate、缓冲区归属 | PL 读到 CPU cache 中尚未回写的数据 |

## 身份链

按下面的链条记录身份；不要求每次都重建，但必须能说明当前产物从哪里来。

```text
运算定义与黄金参考
        ↓
源码 + 参数 + 输入 + 构建配置
        ↓
综合 RTL → 导出 IP → 实际导入的 RTL
        ↓
已布线设计 / bit / XSA / PS 初始化 / ELF
        ↓
实际目标板 + 当前固件 + 本次输入与输出
```

对 HLS 工程，不只比顶层 RTL：枚举参与计算的全部 `.v/.vh`，检查集合与哈希。若导出工具增加仿真专用模块，先核实新增代码的作用与条件；不能用全局忽略规则跳过任意差异。身份清单是审计记录，不是数字签名，也不自动证明上游可靠。

通用清单格式：

```json
{
  "artifacts": [
    {"path": "src/kernel.cpp", "sha256": "64位十六进制SHA256", "bytes": 1234},
    {"path": "data/input.bin", "sha256": "64位十六进制SHA256"}
  ]
}
```

`bytes` 可省略；`path` 相对 `--root`，必须位于该根目录。示例中的摘要文字必须换成实际 SHA256。脚本拒绝空清单、无效摘要和重复路径；它只读取文件，不重写或修复清单。

## 验证阶段

| 阶段 | 观察结果 | 可以得出的结论 | 不能代替的检查 |
|---|---|---|---|
| 静态/编译 | 语法、链接、配置解析 | 当前输入能构建或解析 | 数值、RTL、板测 |
| C 测试 | 独立参考逐元素比较 | 所供输入的 C 功能一致 | DATAFLOW 死锁、总线时序 |
| HLS 综合 | II、latency、资源估计、警告 | 调度与结构可生成 | 最终布线频率、实测吞吐 |
| C/RTL | 新 RTL、驱动刺激、输出/超时 | 所供场景的 RTL 行为一致 | 全空间正确、真实 DDR/缓存 |
| 实现 | 有效约束下 setup/hold、资源 | 当前实现满足已检查的时序 | 板上时钟已生效、准确率 |
| 板测 | 目标身份、固件、输入、输出 | 实际链路对所测输入成立 | 新样本泛化与现场可靠性 |

对于神经网络，硬件与 INT8 参考逐元素一致是部署正确性；FP32/INT8 与真实标签的对照才涉及识别有效性。训练、标定或阈值选择用过的实物，应按实物组从独立评估中排除。同一图片的多裁剪版本和旋转版本不应充当独立实物。

## 测试覆盖选择

按改变范围选场景：零值、正负边界、溢出或饱和附近、随机输入；最小/最大 shape；不满 SIMD/PE 的尾通道；奇数尺寸与池化边界；间歇输入与下游背压；连续多次请求；复位后首个请求。参考生成过程必须保留数据类型与随机种子，不能只用与待测实现同一段错误索引代码生成答案。

大型张量先确认 shape/dtype，再逐元素比较。CRC 适合快速回归；存在 CRC 差异时回到原始张量定位。CRC 一致是强回归信号，但不是独立数学证明。

## 性能口径

记录输入规模、精度、backend、时钟/设备、batch、线程数、cache、预热、重复次数和时间边界。分别考虑：

- 核内部计算时间。
- 从驱动启动到完成的核调用时间。
- 含 DMA/cache/scoring 的板端总时间。
- 含预处理、JTAG/网络与显示的端到端时间。

不要把一种时间除以另一种时间称为加速比。重复测量报告中位数或均值及分布，并注明计时器开销与 UART 是否在区间内。使用 [measurement_example.json](../assets/measurement_example.json) 记录口径。

## 工具或板卡不可用

继续完成源码审查、固定参考、C 测试或静态证据整理中可执行的部分。将不可执行的阶段明确标记为未执行，附上后续命令。不要通过改写已有日志、使用旧截图或推算时钟来补齐验证状态。
