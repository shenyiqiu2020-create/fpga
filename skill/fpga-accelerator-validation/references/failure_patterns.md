# 失败模式与最小排查

以下来自真实移植、HLS 和板测中的问题，参数必须按待处理项目核实。

| 观察 | 优先核对 | 修复后的最小验证 | 不应采用的捷径 |
|---|---|---|---|
| AXI 主口 ACLK 未连接 | 时钟来源、时钟域及该接口是否需要 | BD 校验；需要该通路时做寄存器/存储读写 | 只为消除错误而随意接异步时钟 |
| 源码变了，输出/资源不变 | solution、导出 RTL、实际 IP 仓库和实现 run | 文件集合与哈希，重跑受影响构建 | 仅增加 IP revision |
| `invalid command name ps7_init` | 初始化脚本是否在同一个调试会话中 source | 调用后核对寄存器/DDR 初始化状态 | 把别的会话截图当作初始化已执行 |
| 仿真通过，板上偶发错 | cache、对齐、输出缓冲复用、请求序号 | 连续多输入、CPU/PL 双向内存读回 | 取消缓存后直接宣称根因已确定 |
| DMA 永久 busy | S2MM 是否先就绪、TLAST、实际字节数与时钟复位 | 最小短帧；读 DMA 状态和错误位 | 无限轮询，无截止时间 |
| DATAFLOW 仿真挂起 | 生产/消费数量、跨调用状态、FIFO 容量 | 有背压的最小失败 shape 与 C/RTL | 只把所有 FIFO 改得非常深 |
| DSP 增加但速度不变 | 尾通道、padding、后处理和外存占比 | 同 shape 分阶段计时与资源 | 用 PE 倍数直接换算整网速度 |
| 提频设置已改，但速度无变化 | 已布线时钟约束和板上真实时钟 | 寄存器读回/可测时钟与同口径计时 | 只报告 HLS target frequency |
| XSDB 新会话找不到 APU | 线缆/目标身份、发现延迟、电源 | 有界等待发现，再检查指定目标 | 重复连接不同目标直至某次成功 |
| 原始二进制 mwr 写入异常 | 工具版本、字节/字数、端序 | 短数组写入后逐字读回 | 假定帮助文档的可选参数在所有版本一致 |
| 整数参考与硬件一致，但正常件大量误报 | 独立标签、模型版本、裁剪分布、阈值来源 | 按实物组比较 FP32、INT8 与标签 | 只挑早期高准确率或只报一致性 |
| Git checkout 后工件哈希变化 | `.gitattributes` 与行尾转换 | 比较工作树、Git blob 和交付归档的字节 | 为通过哈希而只重写清单 |

每项结论记录“观察→假设→对照操作→结果”。操作奏效只能支持它检验的假设；涉及多个变量时要进一步区分。若当前项目没有相同症状，不必逐项执行这张表。
