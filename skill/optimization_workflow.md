# 基于证据的 HLS 优化工作流

适用场景：已有可复现计算核、黄金参考和至少一份真实性能记录，希望在数值规则不变时改善速度或资源。

提示词模板：

> 先读取当前源码、实现报告与逐阶段计时。明确数据格式、舍入、饱和、复位、缓存一致性和时钟。提出一个可由测量区分收益来源的修改，建立独立版本，保留原版。依次做 C 测试、对新 RTL 的 C/RTL 对照、综合打包与导入的身份核对、布线后时序、板上参考对比和同条件计时。失败时记录原始错误，修正后再继续；未通过的阶段不得写成已完成。

执行步骤：

1. 固定模型、输入、接口和工具版本，生成哈希清单。
2. 从实际逐层计时中选择瓶颈，写下预期影响与可能代价。
3. 每轮只改变可归因的一组因素，例如本轮只在 PE40、125 MHz 下改变后处理调度。
4. 检查 C 数值正确、HLS II 和资源；C 测试不能证明 DATAFLOW 无死锁。
5. 用新 RTL 跑 C/RTL，对 FIFO 背压、边界尺寸及不满并行通道的情况留覆盖。
6. 固定导出 IP，核对实际 Vivado 导入内容，检查 setup 与 hold。
7. 在同一块板、同一计时口径下比较原版与新版，同时报告失败或变慢的层。
8. 将可复用部分、输入契约、验证效果与失效条件写进 Skill。

已验证效果：本工程的 PE40 后处理重叠版核耗时由 1.787 s 减至 1.484 s，DSP 和 BRAM 不增加，LUT/FF 增加；此数值只适用于报告中的具体板卡和冻结模型。

失效条件：参考输出来源不清、测试集泄漏、使用旧 RTL、时钟未生效、计时范围改变、修改了量化参数但仍沿用旧答案，都会破坏结论。
