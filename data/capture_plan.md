## 首件缺角试样的制作记录（已完成）

1. **当前不用给正常工件逐件贴编号。** 保留已拍的三个正常件；另外拿一件未拍过的工件制作缺角。正式采集时再检查天然缺损、污渍和孔位差异，并通过拍摄记录或分开的收纳盒追踪同一件的多张照片，确保训练、验证、测试不混用同一件；不需要在工件表面写编号。天然异常件单独留存，不进入正常训练集。
2. **先做一件缺角试样。** 用这件在未改动时拍 1 张正面原图，记为同一试样的“改动前”，记录背景、光照和相机即可。改动前照片只作制作记录，**不进正常训练、验证或测试集**。不要破坏已拍的三个参考正常件，也不要一次破坏 15 件。
3. 将这件工件固定好，保护手和眼睛，在一个外角剪掉约 3 mm 的尼龙材料，做出可见缺角；不要在手持工件时让刀具朝向手指。保留剪下部分和处理记录。改动后拍 **4 张**：用两种现有背景，各拍正放和约 45° 斜放一张，其中一张尽量复现改动前条件。记录每张的光照，且都能看到完整外缘。将**整幅原图**先缩至 `256×256` 检查缺角是否还看得见，并记录严重反光、失焦等失败条件。这是已完成的早期试样记录；首版后续只扩展外缘缺损；看不清就先调整拍摄距离或裁剪方案，不继续批量破坏。

此段记录当时扩展缺陷的设想：槽边或肋条断损、明显划痕等都须先通过可见性与独立实物验证。按本页最新决定，**首版不继续制作断肋和划痕件**，优先增加不同部位、程度的外缘缺损。每件只做一种缺陷，记录部位、工具、处理前后照片，明确标注为**人为制造缺陷**，不能写成出厂瑕疵。**原计划的“从背面堵住贯通孔”不适用于这批工件，停止采用。** 若以后要模拟“凹孔被填平”，应另称“人为填平盲凹孔”，先验证填充边缘和颜色不会成为唯一识别线索；不能写成贯通孔缺失。

## 首批试跑的实物分配

旧版的 60 件训练、15 件验证、10 件正常测试、15 件异常测试，以及“每件 3 张、共 300 张”已撤销，不作为拍摄任务。先用小批正常件把模型和阈值跑通，**并行增加独立缺陷件**，每轮查看失败样本再补。下表按实物件数计；逻辑组号只在清单中使用，不要求在工件上标字。

| 集合 | 首批件数 | 用途 |
| --- | ---: | --- |
| 正常训练 | 8 | 学习正常外观；同件所有照片只留在本集合 |
| 正常验证 | 2 | 用正常件定阈值，不参加训练 |
| 正常测试 | 2 | 检查未见过的正常件是否误报 |
| 首版缺陷测试 | 2 | `D01`、`D02` 两件缺角/边缘缺口；`D03` 退出首版统计，等待后续扩展 |

这是**跑通流程和寻找失败原因**的规模，不足以计算可信的准确率。首版优先补不同部位和程度的**外缘缺损**实物，再按正常误报情况补正常件；断肋、划痕等内部缺陷留待扩展。多张照片不等于多件独立工件。

原“每件 3 张、共 300 张”不再作为正式采集目标；多种背景、光照和角度需要先试验覆盖范围，正式照片数待定。每张照片记录拍摄清单中的逻辑组号、背景、光照和大致角度；同一件的照片全部留在同一个集合，拍摄时取下再放回，避免连按快门得到近似副本。测试须既覆盖训练见过的条件，也留出至少一种未用于训练的条件组合，分别报告各条件和整体的误报、检出与定位，不把多张图说成多件独立样本。若某条件下白件和背景混在一起、严重反光、过曝、欠曝或失焦，记为输入失败条件，不能把不清晰图片的检测结果说成模型能力。像素定位指标需要异常图对应的缺陷区域标注；先标注每件异常件的一张照片，正式报告定位指标时说明覆盖照片数。

## 多条件试拍与输入边界

- 第一轮仍用同一台手机或相机、同一镜头和分辨率，俯拍同一正面；相机固定在支架上，便于单独比较方向、背景和照明变化。工件应完整落入拍摄区域，但**不要求转到统一朝向，也不要求固定背景或光照**。背景可用现有棕色板和手边另一块反差明显的平整材料，无须专门购买背景布；强纹理背景可以作为挑战条件记录。背景与光线的组合必须在正常和异常样本中都有，避免模型只凭背景判别类别。
- 试拍阶段分别记录相机型号、镜头、支架高度、光源、背景、拍摄日期和角度；逐项变化可帮助找出失败原因。可以测试不同亮度、色温和阴影，但应能拍清白件表面、外缘和盲凹孔。夹具和标签不能遮住工件或只在某一类别出现。
- 工件四边、两个实心圆和两个盲凹孔都要完整入镜，周围留少量边距；保持拍摄距离和工件大小接近，**记录而不限制平面旋转角度**。先查看原图，再查看缩放到 `256×256` 的预览：正常圆形特征、首版外缘缺损应可辨。严重过曝、反光、失焦或工件与背景无法分开时，记录并作为当前输入边界，不凭空宣称算法能恢复已丢失的细节。早期手持、木纹和棕色纤维底板照片只作试拍参考，不直接计入正式数据。
- 保存相机原始文件，不经聊天软件压缩或加滤镜。文件名用拍摄清单中的逻辑组号、条件和张数区分，例如 `N01_green_01.jpg`；无需在工件表面写字。不要用可见贴纸、彩笔或背景差异暗示类别。原图与标注放在 Git 忽略的 `build/work/data/tie_mount/`；`data/` 中只放采集规范、匿名清单和必要的获取说明。上传公开仓库前另核对图片、人物信息和授权。

**下一步：** 保留 `D01`、`D02`、`D03` 三件实物；当前无需继续破坏或重复导出照片。A 工作线继续 EfficientAD 主线：先检查现有 300 步实物试跑的裁剪、归一化 NaN、背景与方向误判，再用身份可追溯的正常件分别建立训练/验证/测试集合，并用独立的外缘缺损件测试两类异常图、融合判定和定位。让正常/缺陷两类都覆盖相同背景、光照和方向；阈值只由训练/验证件确定，留出未见过的实物测试。外缘几何基线作为辅助对照，不能代替网络成绩。若未来重新纳入 `D03`，须重新定义多视角采集和相应验证，不能混入首版成绩。

## 少量正常图怎样拍

EfficientAD 主线的首批分组计划使用 **12 件不同的无明显缺陷工件**（8/2/2 件训练/验证/测试），每件先拍两张正面原图；这是模型排错规模，**不是当前要求用户立刻补拍 24 张的任务**。现已能追溯身份的 `N01`、`N02` 可计入后续相应集合，但两件不能同时满足三个互不重叠的正常集合。正常件外形相似正是模型应学习的基线；换实物是为防止同一件的多张照片同时出现在训练和测试中。背景、方向和光照在两类工件中交错，不让类别与拍摄条件绑定。

不用在工件上贴编号。拍摄时按顺序从“训练”“验证”“测试”三个临时收纳盒分别取放，一件拍完两张再放回原盒，手机文件名/拍摄记录记逻辑组号 `N01` 等即可；若顺序弄乱，先停拍核对，不能猜同一件的归属。每张都拍完整外缘，相机保持俯拍正面、同镜头，照片不过曝、不失焦。先保留手机原图，不通过聊天软件二次压缩作为正式训练文件。后续是否增加正常件由误报和条件覆盖决定，优先级低于补充可见且多样的缺陷来源。

## A 已实现的本地输入流程

首版外缘基线可以直接对单张图片运行，不要求在拍摄时把工件旋正。例如：

```powershell
python -m src.tie_mount_outline "D:\工件照片\do1\a9d6888b54b14a6623a2b4f956d1d2c3.jpg"
```

输出包含 `corner_loss_score`、`angle_mod_90_degrees`、`weakest_corner_xy_source`、`crop_box` 和 `provisional_verdict`。其中的角度估计是算法内部处理，不能把结果解释成工件必须摆正；疑似角只是外缘损伤的粗定位，不能当精确缺陷掩码。`--threshold` 默认 `0.35` 仅供排错，正式判定应从**独立验证实物**定阈值，再在新实物和未见的背景/光照组合上测试。此几何基线适用范围是完整入镜的近俯拍白色方件、可区分的背景和可见外轮廓；它不会识别 `D03` 内部断肋，也不能保证严重透视、遮挡、过曝或与白件同色背景下有效。EfficientAD 作为主体须让训练、验证、测试的正面旋转条件一致覆盖，并单独检查它的旋转鲁棒性；几何基线的成功不能当作 EfficientAD 已改好。

`src/tie_mount_crop.py` 曾在 9 张正常、`D01` 的 4 张及 `D02` 的 4 张试拍 JPEG 上逐张输出裁剪图；新版更严格的边界核对会拒绝其中一张 `D02` 斜放图。`D03` 原始四张常规图中，绿色正放和棕色斜放仍可用，另两张由本次补拍代替；原始局部近拍和贴边图在新版中均被拒。两张补拍图经人工查看 `256×256` 裁剪，完整外缘和断损可辨。**自动裁剪成功不代表照片合格**，对新背景、复杂纹理、侧视、遮挡或严重反光也可能拒绝或裁错，仍需逐张检查。`sim/prepare_tie_mount_dataset.py` 根据 CSV 中的同一实物 `object_group` 阻止跨训练、验证、测试集，并在 `build/work/` 中输出裁剪图及 `prepared_manifest.json`（原图 SHA-256、背景记录和裁剪框）；不修改原图。它要求训练、验证、测试正常图及至少一张测试异常图。恢复聊天图的 300 步试跑不满足这一正式独立实物划分要求，不能报告可推广的检测成绩。

在仓库根目录建立 Git 忽略的 `build/work/data/tie_mount/`，将原图放进去，并在同目录建立 `manifest.csv`。一行代表一张照片；同件两张的 `object_group` 相同，`split` 同为 `train`、`validation` 或 `test`。CSV 表头为 `file,object_group,split,label,background,angle,light`。例如：

```csv
file,object_group,split,label,background,angle,light
N01_green.jpg,N01,train,good,green,0,soft
N01_brown.jpg,N01,train,good,brown,35,room
N09_green.jpg,N09,validation,good,green,20,soft
N11_brown.jpg,N11,test,good,brown,45,room
D01_green.jpg,D01,test,missing_corner,green,0,soft
D02_brown.jpg,D02,test,edge_notch,brown,35,room
```

示例行仅说明格式，须以真实文件名和拍摄记录替换；`D01`、`D02` 是首版两件缺角/边缘缺口工件的逻辑组号。`D03` 是第三件斜肋断损工件，**不能放进首版 `test` 目录，也不能改标 `good`**。只将人工确认合格的常规视角原图列入正式清单。执行：

```powershell
python -m sim.prepare_tie_mount_dataset --manifest build/work/data/tie_mount/manifest.csv --output-dir build/work/data/tie_mount_prepared_v1
```

然后逐张检查 `build/work/data/tie_mount_prepared_v1/tie_mount/` 中的裁剪图。候选 EfficientAD 实现用 `--dataset mvtec_loco` **仅借用其独立 `validation/good` 目录读取方式**；数据本身仍是自采扎带座，并非 MVTec LOCO。使用隔离环境中的 Python 3.10，第一次只跑少步确认训练、验证和异常图能完整输出：

```powershell
& build/work/efficientad-env/Scripts/python.exe build/work/external/efficientad/efficientad.py --dataset mvtec_loco --subdataset tie_mount --mvtec_loco_path build/work/data/tie_mount_prepared_v1 --weights build/work/external/efficientad/models/teacher_small.pth --output_dir build/work/results/tie_mount_pilot_v1 --train_steps 1000
```

`sim/export_efficientad_components.py` 已支持 `--validation-root build/work/data/tie_mount_prepared_v1/tie_mount/validation`，用于独立正常验证图设阈值并校验异常图。训练图绝不用于设阈值，测试图绝不用于调整阈值。当前 EfficientAD 输出异常分数/图，但不能可靠地把缺角、断筋等自动命名为具体类别；首版只评价可见外缘缺损。将来若要区分缺陷类型，需要更多独立缺陷件及相应标签，再单独验证分类方案。首版仅两件异常实物，即使每件有多张，也不能据此估计可靠检出率、跨背景泛化能力或定位精度；正式报告要等更多**独立异常件**和异常区域标注。

## A 工作线接手

候选外部实现按 MVTec 风格目录读取 `train/good`、`test/good` 和缺陷子目录，预处理会缩放到 `256×256`。其 `mvtec_ad` 模式把训练图片**逐张随机**分出 10% 做验证，会令同一实物跨集合；本队用已实现的 CSV 实物分组、独立 `validation/good` 和候选脚本的 `mvtec_loco` 目录读取分支避免正式数据中的此问题。聊天恢复图已完成 300 步电脑端试跑，但正常图缺少身份映射，**尚未完成独立实物评估**。公开 `bottle` 结果不能直接当作此工件的已验证模型；需要在正常工件图上训练或适配并独立评价。板端与 RISC-V 课程路线仍由各自工作线验证。

**多条件处理待实现与验证：** 先试工件定位与裁剪，减少背景进入模型的面积；再试正常图的平面旋转、亮度、对比度与色温增强，检查裁剪和背景填充不会产生黑角等假特征。预处理参数只用训练/验证工件确定。若效果不足，再比较定位后旋转归一化或背景分离；输出的异常图和缺陷位置须变换回原照片坐标。增强不能保证未见背景或强反光下有效，也可能掩盖细微缺陷，需用独立工件分别报告各背景、光照、角度的正常误报、异常检出和位置。保留未参与训练的条件组合供压力测试；若只通过部分条件，就只报告通过的范围。板端资源和时延需另评估。
