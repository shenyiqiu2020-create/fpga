# 报告与交接资料

对应比赛规则第 3.3.5.3 和 3.3.5.4 节，保存设计依据、实现与优化过程、复现说明以及大模型协作记录。

## 设计报告应包含

1. 选题背景、规则工件的检测需求、已有方法和创新点。
2. 检测流程、功能框图、EfficientAD 教师/学生与自动编码器分支的设计原理；若后续采用几何约束，另列其作用和验证。
3. PS/PL 划分依据、网络轻量化、量化策略及接口设计。
4. 硬件、工具和依赖版本；采用非推荐工具版本时说明原因。
5. 功能验证、误差分析、板级实测及与基线的比较。
6. 优化前后性能与资源对比，说明参数、数据和测试条件。
7. 技能包的经验来源、验证过程、效果与适用边界。
8. 从零开始的完整复现步骤，给出各阶段命令与预期输出。

## 大模型协作记录应包含

- 任务背景与提示词。
- 模型回答及其中提出的假设。
- 实际验证、失败现象和修改依据。
- 自我纠错轨迹及最终采纳的方案。
- 智能体工作流设计（如实际采用）。

记录应关联具体源码版本与验证证据。性能指标与测试结果填写实际数据，未完成部分标记为待验证。

## 接手入口与维护

1. [项目工作交接报告](team_outline.md)：当前状态快照、工作线、交付物和检查点。
2. [项目工作记录](progress.md)：按时间记录实际改动、原因、运行方法、验证结果、未完成事项和下一步；新证据先写在此处。
3. [规则核对表](contest_rules.md)：AMD 自主选题赛道的已核对条款和待确认事项。
4. [EfficientAD 迁移计划](efficientad_plan.md)：论文、候选代码、数据来源及各阶段通过条件。
5. [GitHub 协作步骤](collaboration.md)：分支、提交、审查和同步方法。

目前尚无完整设计报告、完整大模型交互档案或板级功能验证记录。提交新结果时同步更新根目录 [README](../README.md) 和进度记录，说明可运行命令与证据位置。

进度记录不能代替指南要求的提示词、模型回答和自我纠错轨迹；提交材料须另附真实交互与纠错证据。A/B/C 是工作线代号，执行人仍待团队确定。像素模板软件演示与 EfficientAD、板级结果分别记录。
