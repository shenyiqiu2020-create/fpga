# 设计报告与大模型协作记录

对应比赛规则第 3.3.5.3 和 3.3.5.4 节，保存设计依据、实现与优化过程、复现说明以及大模型协作记录。

## 设计报告应包含

1. 选题背景、规则工件的检测需求、已有方法和创新点。
2. 检测流程、功能框图、教师-学生分支与几何约束的设计原理。
3. PS/PL 划分依据、网络轻量化、量化策略及接口设计。
4. 硬件、工具和依赖版本；采用非推荐工具版本时说明原因。
5. 功能验证、误差分析、板级实测及与基线的比较。
6. 优化前后性能与资源对比，说明参数、数据和测试条件。
7. 技能包的经验来源、验证过程、效果与适用边界。
8. 从零开始的完整复现步骤，给出各阶段命令与预期输出。

## 大模型协作记录应包含

- 任务背景与提示词。
- 模型回答及其中提出的假设。
- 实际验证、失败现象和修改依据。
- 自我纠错轨迹及最终采纳的方案。
- 智能体工作流设计（如实际采用）。

记录应关联具体源码版本与验证证据。性能指标与测试结果填写实际数据，未完成部分标记为待验证。

开发过程请持续维护 [progress.md](progress.md)，按照“本次改动、原因、验证、未完成与下一步”记录真实状态。队员首次参与项目可阅读 [collaboration.md](collaboration.md)。目前尚无完整设计报告或板级功能验证记录。

在着手新任务前阅读 [AMD 自主选题赛道规则核对表](contest_rules.md)。进度记录不能代替指南要求的提示词、模型回答和自我纠错轨迹；后续需将实际交互证据整理成可提交的大模型协作记录。

当前竞赛目标及数据集到板端的阶段判据见 [EfficientAD 迁移计划](efficientad_plan.md)；不要把旧的像素模板软件演示当成该模型或板级结果。
