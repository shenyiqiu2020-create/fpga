截图要求压缩包包含以下材料：

1. PDF 格式报告。
2. 按标准目录结构整理的**代码**；去除编译中间文件、仿真波形、FPGA 综合中间文件等非必要文件。源工程、约束、构建脚本和必要配置应保留，不能为了缩包而丢失复现所需输入。
3. 必要佐证材料，例如参考文献目录、开发日志、实验过程、排错记录、版本管理记录。
4. 使用生成式 AI 时的详细提示词、Skills、AI 引导过程，以及 AI 生成代码的验收过程记录。只写“使用了 AI”或只附生成代码不够；记录应能对应到实际代码版本和测试。
5. 实物演示视频，**不超过 10 MB**。

所有材料打包后**不超过 30 MB**。提交前以实际压缩包和视频文件大小复核；截图没有给出报告页数、指定处理器型号或具体的课程评分细则，不能自行补成硬性规定。

## 对现有方案的影响

竞赛版继续以 ALINX Zynq-7020 的 ARM PS 负责输入输出、PL 执行经过验证的计算模块为目标。课程版在此基础上另建**能运行程序的 RISC-V SoC**，明确处理器、指令/数据存储、互连、控制/输出外设与扩展 IP 的连接。优先复用竞赛版的软件黄金参考和一个边界清楚的特征差分/评分算子，减少两套应用的数据定义分歧。课程版程序至少要配置 IP、触发计算、读取结果并输出异常分数/位置或判定；输入可以先用固定的已知特征张量，不把这个小系统称为完整 EfficientAD 图片推理。若改用其他 IP，须说明与工件检测应用的关系及验证方法。

| 当前证据 | 课程要求中的缺口 | 完成判据 |
| --- | --- | --- |
| 电脑端 `bottle` 数据的候选 EfficientAD 训练、推理及评分图参考；尚未取得扎带座照片 | 真实工件适配与可供硬件比对的固定输入/输出 | A 固定样本、预处理、张量布局、量化/容差和黄金结果；公开数据集成绩与自采件成绩分开记录 |
| 仓库尚无 PL 算子、板级工程或 RISC-V 核 | RISC-V、扩展 IP、存储/总线与嵌入式软件组成可运行应用 | C/B 给出源码、连接图、程序、构建命令、仿真和板上运行日志；RISC-V 对 IP 的实际读写有可复核记录 |
| 目前主要是进度和交接文档 | PDF 报告、完整设计/验证、AI 使用与验收记录、演示视频及体积控制 | 按上节逐项核对压缩包，实际视频 ≤10 MB、总包 ≤30 MB；报告和日志中的板上结果有真实运行证据 |

因此，**技术方向无需因截图放弃 EfficientAD 或改成 ARM-only 课程版**；课程线需要从“预留 RISC-V SoC”升级为有真实程序、IP 接口和验证证据的独立交付。竞赛与课程的“完成”分别判断。RISC-V 与完整 EfficientAD 同时全部迁入 PL 的可行性尚未评估，不作为目前承诺；若资源或时间不足，课程最小系统可验证评分算子及固定输入，竞赛版则如实说明模型各部分实际运行在 PS、PL 或电脑端的位置。课程最小系统是否满足教师对“完整应用系统”的具体判定，需拿架构与演示范围向教师确认，不能仅凭本页自认通过。

## 接手与近期动作

- **A（算法/数据）**：工件已下单、尚未到货；先冻结可公开复核的一组模型输入、特征张量和评分黄金输出，向 B/C 说明许可、形状、定点范围与误差容限。到货后试拍并按实物编号划分数据，不把 `bottle` 成绩当作工件成绩。
- **B（板卡/系统）**：确认整板型号和环境，建立竞赛版启动/文件输入输出；与 C 定课程版 RISC-V 程序装载、串口/结果输出和现场视频采集方式。
- **C（PL/课程 SoC）**：先给出扩展 IP 的寄存器/数据接口和软件黄金比对，再落实 RISC-V 核、存储、互连、嵌入式程序和可重建工程；记录仿真、综合/实现、上板结果及资源限制。
- **共同交付**：从现在起保存开发、排错、版本记录和实际 AI 交互/生成代码验收证据；最终打包时只纳入授权可提交的代码与数据，复核 PDF、目录、视频和压缩包大小。

截至 2026-10-13，本页只是要求核对和方案调整记录：没有课程版 RISC-V SoC、扩展 IP 上板结果、课程报告或实物演示视频。工件下单不等于到货或完成实物测试。最新实际结果与变更见 [项目工作记录](progress.md)。
