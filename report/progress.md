**新输入：** 用户把照片放在 `D:\工件照片`，文件夹 `正常1`、`正常2`、`do1`、`do2`、`do3` 各两张，合计 10 张 `1279×1706` JPEG。它们分别代表五件实物，两张是同件的近正放和约 45° 平面旋转；均为棕色背景的近俯拍。按原字节复制至 Git 忽略的 `build/work/data/tie_mount_20261025/raw/`，`inventory.csv` 记录来源组号、SHA-256、尺寸、视角、首版范围与试验分数；复制前后哈希一致。`D01`、`D02`、`N01`、`N02` 共 8 张用于首版外缘检查；`D03` 两张只作范围外参考。现有两件正常件不足以分别构成训练、验证和测试集合，因此本次未以它们重新训练 EfficientAD，也不报告独立准确率。

**算法：** `src/tie_mount_outline.py` 在 `src/tie_mount_crop.py` 定位后的 `256×256` 图上获取白色前景，搜索 0–90° 内最小外接矩形方向，再比较四角白色占用量；返回连续 `corner_loss_score`、临时阈值判定和疑似缺损角的原图坐标。此法针对**外轮廓缺损**，不需要用户摆正工件，也不识别内部斜肋。当前 8 张首版照片全部裁出完整外缘：`D01` 两张分数 `0.5919/0.5357`，`D02` 为 `0.7443/0.7595`，四张正常照为 `0.0238–0.1613`；暂定阈值 `0.35` 下与这 8 张肉眼标签一致。把每张裁剪图在软件中另转 13°、29°、67°，每次分数仍留在原判定侧。合成方形的 0°、17°、35°、62°、83° 旋转回归测试也通过。这是同源图片和合成图上的几何检查，**不增加独立实物数，也不是跨背景或现场检出率**。`D03` 两张分数 `0.0763/0.0255`，无外缘缺损的输出符合首版范围，不能称为断肋漏判或断肋检测成功。

**复核方式：** 在仓库根目录运行 `python -m src.tie_mount_outline "D:\工件照片\do1\a9d6888b54b14a6623a2b4f956d1d2c3.jpg"` 查看逐图 JSON；`python -B -m unittest sim.test_tie_mount_outline -v` 检查非训练角度。输入原图留在本机 Git 忽略目录，不加入公开仓库。算法目前依赖白件与背景的亮度/颜色反差及完整近俯拍轮廓；`0.35` 阈值是在当前 8 张上试用，正式使用必须用其他独立实物的验证集定标，并用新实物测试。先前 EfficientAD 在聊天恢复图上的失败结果仍如实保留，几何基线的局部成功不能替代完整模型复现、PL 实现或课程 RISC-V 验证。

**额外边界核对：** 旧聊天附件中 `D02` 的四张绿色/棕色照片有三张经当前裁剪器和外缘基线给出缺损分数 `0.7137–0.7599`；另一张因外缘贴近画面边界被拒。这些仍是同一件 `D02`，不能增加缺陷实物数量，也不能据此宣称跨背景泛化。旧拼图恢复的 `D01` 图块是有损裁片，当前外缘掩膜不可靠，不纳入此基线验证。

**下一步：** 无须补拍 D03 的斜俯视，也无须重复导出这 10 张。先在新背景、不同照明和更多未见的平面方向上，用**同类正常与外缘缺陷件配对采集**来检查定位和误报；后续再增加不同外缘缺损位置/程度的独立实物，按实物分开定阈值和测试。EfficientAD 是比赛主算法，继续推进其旋转/背景适配与板端迁移，不能把本几何结果当作该网络已有性能。

**怎样验证：** 在仓库根目录运行 `python -m unittest discover -s sim -v`，本次在 Python 3.12.14、NumPy 2.3.5 环境中实际运行 3 项数值检查，全部通过（`Ran 3 tests ... OK`）。本机 NumPy 已安装，因此未实际执行依赖安装命令；其他队员第一次运行可先执行 `python -m pip install -r requirements.txt`。CLI 用法见根目录 README。此结果仅覆盖软件参考公式和输入检查。

**限制和未完成：** 没有训练好的教师与学生网络，没有真实样本异常图、几何判定和阈值；也没有量化标定参数或 FPGA 实现。INT8 路径要求两组特征采用相同尺度和零点，代码不能从 `int8` 数据类型自动验证这一点。整数均值向下取整，与浮点输出有量化误差。任何检测精度、延迟、吞吐和资源数字都尚未测得。
