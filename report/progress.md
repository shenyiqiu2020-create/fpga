## 2026-10-11：电脑端图片输入、判定与结果保存

**起点与 Git：** 开工时 `main`、本地记录的 `origin/main` 和 `feat/score-map-docs` 均指向 `14bb78d`，工作区干净，说明此前评分图提交已进入本地 `main`。未执行远端 Fetch，不能据此断言 GitHub 当下没有新提交。本次在 `codex/image-baseline` 分支修改，不改写历史。

**做了什么：** 新增 `src/image_baseline.py`，读取同尺寸、已对齐的正常参考图片和待测图片，转成归一化灰度，复用 `score_map_float` 计算逐像素平方差；按阈值和四连通面积过滤异常，保存 `score.npy`、`score.png`、`mask.png`、`overlay.png`、`result.json`。JSON 给出正常/异常判定、区域数、异常像素数和坐标。新增 `sim/make_demo_images.py` 生成人工正常、缺角、缺孔图片，新增 `sim/test_image_baseline.py` 验证端到端流程和输入检查。补充 Pillow 依赖及 README、目录说明和协作说明。

**为什么：** 图片输入到可查看、可保存的结果是当前不依赖板卡和真实数据即可完成的最小闭环。采用简单像素模板，是为了先验证文件、数值、判定和输出接口；它不是 EfficientAD 教师/学生推理，也不具备位置变化、光照变化下的可靠性。模拟图片由项目代码生成，不使用外部数据集或权重，不产生任何真实准确率结论。

**如何运行：** 仓库根目录执行 `python -m pip install -r requirements.txt`（本机依赖已存在，未重装），然后 `python -m sim.make_demo_images --output-dir build/work/demo_inputs`。用 `python -m src.image_baseline build/work/demo_inputs/normal.png build/work/demo_inputs/missing_corner.png --output-dir build/work/demo_corner` 检查缺角；将 `missing_corner` 改为 `missing_hole`、输出目录改为 `build/work/demo_hole` 检查缺孔。参数和输出说明见根目录 README。

**如何验证：** 本机 Windows、Python 3.13.0、NumPy 2.4.4、Pillow 12.2.0。修改前 `python -B -m unittest discover -s sim -v` 为 3 项通过；修改后为 6 项通过。命令行实际生成三张 128×128 模拟图片，缺角输出 `defect`、1 区域、256 像素、框 `[24,24,40,40)`；缺孔输出 `defect`、1 区域、144 像素、框 `[71,71,83,83)`。测试还检查正常图判为 `normal`、结果文件可读、错尺寸与无效参数被拒绝、小噪点被过滤。所有输出均是电脑端软件结果，写在 Git 忽略的 `build/work/`。

**尚未完成与风险：** 像素模板要求固定相机、固定工件位置和稳定照明；轻微平移也会造成误报。阈值 `0.25` 与最小面积 `9` 只针对模拟图，未经真实验证集标定。尚无真实样本、误检/漏检评估、教师/学生模型、摄像头输入、显示界面、PL 加速器、RISC-V SoC 或板级输出。JSON 的 `defect` 仅表示差异超过规则，不区分缺角和缺孔。

**下一步与交接：** 一位队员确认板卡完整型号、现有镜头/相机或可接受的图片文件输入、显示/存储方式及 Vivado/Vitis 版本；一位队员用固定工件和光照拍摄正常、缺角、缺孔样本并登记来源、拍摄条件及训练/验证/测试划分；一位队员用本文命令在独立电脑复现，再用真实图片记录误报、漏报及失败案例。收集这些证据后再决定是否引入教师/学生模型及哪个算子放进 PL。

## 2026-10-10：建立可核对的软件参考与协作入口

**起点：** 队长仓库的下载包包含 `src/`、`sim/`、`board/` 等目录及说明文件；未发现训练脚本、权重、RTL/HLS、构建工程或板级测量结果。此次工作基于该下载包，不代表已经合入 GitHub。后续若仓库有其他队员的新提交，合入前先比较差异。

**做了什么：**

1. 新增 `src/score_map.py`：输入已对齐的教师、学生 `[C,H,W]` 特征，计算逐点平方差并按通道取均值，输出 `[H,W]` 异常评分图；同时提供整数参考路径。可用 `.npy` 文件从命令行运行。
2. 新增 `sim/test_score_map.py` 与 `requirements.txt`：覆盖异常位置和数值、INT8 极值计算不溢出、错误形状拒绝。
3. 更新根目录与 `src/`、`sim/`、`report/` 的说明；增加本记录和 [GitHub 协作步骤](collaboration.md)。

**为什么这样做：** 后续若要把特征差分、平方和通道累加放进 PL，需要一份明确的数值参考来比对量化和硬件输出。先把输入布局、输出和整数中间位宽写明，便于不同组员实现同一公式。此模块只解决评分图计算，不能证明网络有效或硬件可运行。

**怎样验证：** 在仓库根目录运行 `python -m unittest discover -s sim -v`，本次在 Python 3.12.14、NumPy 2.3.5 环境中实际运行 3 项数值检查，全部通过（`Ran 3 tests ... OK`）。本机 NumPy 已安装，因此未实际执行依赖安装命令；其他队员第一次运行可先执行 `python -m pip install -r requirements.txt`。CLI 用法见根目录 README。此结果仅覆盖软件参考公式和输入检查。

**限制和未完成：** 没有训练好的教师与学生网络，没有真实样本异常图、几何判定和阈值；也没有量化标定参数或 FPGA 实现。INT8 路径要求两组特征采用相同尺度和零点，代码不能从 `int8` 数据类型自动验证这一点。整数均值向下取整，与浮点输出有量化误差。任何检测精度、延迟、吞吐和资源数字都尚未测得。
